Code that behaves the way people already expect.

intent-engineering is a Claude Code plugin. Five review lenses name the surprise, score it, and propose a fix. Use it on a plan, a change, or a whole codebase.

Install in Claude Code Release v0.8.0
Claude Code 
# in any repo, inside Claude Code
/plugin marketplace add https://github.com/davidteren/intent-engineering
/plugin install intent-engineering

Then run /ie-init if you want project policy. Defaults work with no config. Version 0.8.0. MIT.

One reviewer per kind of surprise

Each lens reads its own heuristics. Two always run. Three switch on by context. A finding that you cannot tie to a broken expectation is not a finding.

Predictability
always on
Name and behaviour mismatches, hidden side effects, surprising returns, silent failures, preview that does not match the result. least-astonishment · DWIM · WYSIWYG
Convention
code
Reinvented conventions, config where convention exists, one-offs that fight the repo or framework. Reads your CLAUDE.md and AGENTS.md first. convention-over-configuration · framework idiom
Simplicity
always on
Needless abstraction, speculative generality, knobs nobody sets. Also guards against cutting a real requirement. Occam · KISS · YAGNI
Experience
user-facing UI
Missing interaction states, controls that lie, form and destructive-action gaps, broken keyboard and focus, accessibility gaps, weak information architecture. HIG · look and feel · UX
Architecture
Rails, Python, Laravel, Express, Phoenix, React
Fat models and controllers, God objects, misused services, callback hell, queries in views, layer leaks. Classifies design patterns against a per-stack catalog. structural quality · design patterns

Run the lenses where the work is

Six skills. Four review contexts, plus setup and PR learnings. Fresh is first config. Upgrade adds missing keys and keeps your notes.

/ie-init

Set up or upgrade

Wizard for .intense/. Monolith or multi-repo placement, auto CI sources, severity align, pattern preference, thresholds, and calibrate.

/ie-plan-assist

While planning

An advisory checklist of the principle decisions to get right now. Non-blocking.

/ie-validate-plan

Before coding

Dimensional 0–10 ratings on a plan or spec, plus the design gaps to resolve first.

/ie-review

On a change

Findings by severity on a PR, branch, or local diff. Applies safe verified fixes. Never pushes.

/ie-audit

On a codebase

A posture report: per-dimension scores and the top gaps to fix first.

/ie-from-pr-learnings

After review

Mine PR threads into notes, sources, and severities so the next run enforces what humans already fought for.

Fan out, gate, report

The same loop for validate, review, and audit. Confidence below 75 is suppressed, except a P0 that still has 50 or more.

  1. Select

    Walk up to the nearest .intense config. Pick the lenses that fit the context.

  2. Fan out

    Each lens runs as a parallel sub-agent against its own heuristics.

  3. Gate

    Merge, dedup, and confidence-gate. Agreement across two lenses promotes a finding.

  4. Report

    A ranked report with the broken expectation and a concrete fix for each finding.

Grounded, not vibes

  • A researched knowledge base ships in the plugin: principles, per-framework conventions, and cross-cutting topics. Each has a violation-smell checklist and cited sources.
  • Confidence anchors are 0, 25, 50, 75, and 100. Findings gate at 75. Critical surprises survive lower.
  • When two principles conflict, the lens names the tension and presents the trade-off. It does not dictate.

Tunable and read-only

  • .intense/ config walks up from the working directory. Project values override plugin defaults.
  • Read-only by default. Only /ie-review applies gated_auto fixes locally, and it never pushes.
  • A 141-check contract suite runs in CI on every PR, so the plugin keeps its own promises.

Optional Grok runtime

Claude Code is the installable plugin. This repo also ships a Grok workflow so a review can run as a background script. Marketplace install does not include it.

What it does

  • A config agent picks lenses. Those lenses run read-only.
  • One skeptic checks each finding. Missing evidence is not a yes.
  • Merge is read-only. The report is run scratch. Watch /workflows.
  • It does not apply product-code fixes. Interactive apply stays in /ie-review.

How to run it

  • Clone the repo. Open a Grok session in that directory.
  • Run /workflow ie-review {"target":"origin/main...HEAD"}
  • The script does not apply smell-first severity align or pattern policy, and it does not write docs/.
  • Details: .grok/workflows/README.md
